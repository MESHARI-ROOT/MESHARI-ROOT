# MESHARI-ALOTAIBI — المكتبة المجانية والمدفوعة

نظام ويب عربي لإدارة العملاء والاشتراكات ومكتبة السكربتات، بإدارة مشاري العتيبي.

## الوظائف المنفّذة

- حساب مالك واحد، بلا كلمة مرور افتراضية أو تسجيل مدير من الواجهة العامة.
- رموز دخول يحددها المالك، من 9 أرقام، مع دعم الأرقام العربية والأصفار في البداية.
- تاريخ انتهاء لكل اشتراك، تمديد بالأيام، إيقاف وتفعيل، وتغيير الرمز.
- تعيين السكربتات لكل عميل أو السماح بكل المنشور، وحدّ 1–5 جلسات متزامنة.
- سجل الدخول والتنزيل وتعديلات الإدارة، وآخر نشاط والجلسات وإلغاؤها.
- قسم عام للسكربتات المجانية والمدفوعة، مع أسعار بالريال. المجاني المنشور متاح للتنزيل دون رمز؛ المدفوع يتطلب اشتراكًا وصلاحيات.
- تجديد اشتراك مع إصدار رمز جديد اختياري، وإلغاء الرمز والجلسات السابقة، ونسخ رسالة جاهزة للعميل.
- مكتبة ملفات خاصة، شرح ومتطلبات وتركيب واستخدام وسجل تحديثات. الحد 2 MiB للملف.
- التحقق من SHA-256 عند التنزيل، ومعاملات قاعدة بيانات وحماية من تعارض التعديلات.
- واجهة عربية سوداء وذهبية، شعار MESHARI ومقدمة مركبة فضائية وتحريك اليد وخيار تقليل الحركة.
- خطوات تركيب وفحص WebHID مع فتح أدوات Cronus الرسمية. كتابة السكربت وتحديث البرنامج الثابت تتم داخل أداة Cronus، وليس داخل هذا الموقع.

## GitHub والاستضافة

المستودع يحفظ الكود. تشغيل النظام الكامل مصمم لـ Netlify Functions وNetlify Database (PostgreSQL).
GitHub Pages وحده لا يشغّل الخادم أو نظام الاشتراكات. كذلك رفع مجلد `dist` وحده إلى Drop ينشر الواجهة فقط؛ لا ينشئ نظام الدخول وقاعدة البيانات.

1. المصدر موجود في المستودع العام `MESHARI-ROOT/MESHARI-ROOT`، وملف `package.json` في الجذر. أسماء العملاء وملفات السكربتات ومفاتيح التشغيل ليست ضمن المستودع.
2. في Netlify اختر إضافة مشروع من مستودع GitHub، وحدد المستودع. الإعدادات موجودة في `netlify.toml`: أمر البناء `npm run build` ومجلد النشر `dist`.
3. ثبّت Node.js 22.9 أو أحدث، وnpm 11.9.0 على الكمبيوتر. افتح المجلد في Visual Studio Code أو Visual Studio باستخدام Open Folder.
4. شغّل `Setup-Admin.cmd` على Windows أو `npm ci` ثم `npm run setup` في الطرفية. اختر اسم المدير وكلمة مروره. تُنشأ `.env` خاصة، ولا تظهر كلمة المرور أثناء كتابتها.
5. أضف القيم `ADMIN_USER` و`ADMIN_PASSWORD_HASH` و`AUTH_PEPPER` إلى متغيرات بيئة مشروع Netlify، مع إتاحتها للـ Functions. استخدم القيم من `.env` دون علامات الاقتباس المحيطة بها. أو استخدم `Deploy-Netlify.cmd` لربط المشروع واستيرادها عبر CLI.
6. فعّل Netlify Database للمشروع، وتأكد من ملاءمة خطة الحساب وتكاليف قاعدة البيانات. ملفات إنشاء الجداول موجودة في `netlify/database/migrations` ويطبقها نشر Netlify المدعوم.
7. أعد النشر بعد ضبط البيئة والقاعدة. افتح `/api/health` وتحقق من `ready: true`، ثم افتح `/#login` واختر دخول الإدارة.
8. أضف سكربتًا وعميلًا تجريبيًا، واختبر الدخول والتنزيل والإيقاف قبل مشاركة الرابط مع العملاء.

احتفظ بنسخة آمنة من `AUTH_PEPPER` ولا تغيّره في مشروع قائم؛ تغييره يبطل مطابقة رموز العملاء. لا ترفع `.env` إلى GitHub أو مجلد النشر. حُجب الملف في `.gitignore`. لا تضع ملفات العملاء داخل `public`.

## التطوير والتحقق

```sh
npm ci
npm run check
npm test
npm run build
```

بعد ربط Netlify وإعداد المتغيرات، يمكن تشغيل `npm run dev`. الاختبارات تستعمل PostgreSQL داخل PGlite مع بيانات اختبار معزولة. workflow مرفق لتشغيل التحقق على GitHub عند الدفع وطلبات الدمج؛ تُراجع نتيجة التشغيل من تبويب Actions بعد الرفع.

## حدود التحقق الحالية

نجحت 30 حالة اختبار محليًا، تشمل فصل المجاني عن المدفوع، منع تسريب الملفات المدفوعة، التجديد وتغيير الرموز وإلغاء الجلسات، وتوفر تحديثات السكربتات للمشترك الساري فقط. لم يكتمل النشر على حساب Netlify ولا اختبار قطعة Zen حقيقية. الحزمة لا تتضمن منتجات أو عملاء أو مفاتيح إنتاج.

الاشتراكات هنا لإدارة المدد والصلاحيات يدويًا؛ لا توجد بوابة دفع أو فوترة تلقائية. سجل النشاط يحتفظ بآخر 90 يومًا عند تشغيل مهمة التنظيف اليومية في Netlify. «نشاط حديث» يعني طلبًا خلال آخر 3 دقائق، وليس إثبات وجود الشخص أمام الجهاز.

## إدارة المجاني والمدفوع

1. من إدارة السكربتات، اختر «مجاني» أو «مدفوع». الملفات القديمة تبقى مدفوعة لحماية الوصول إليها.
2. المجاني سعره صفر؛ المدفوع يقبل سعرًا بالريال، أو صفرًا لإظهار «السعر لدى مشاري». لا يعني السعر صفرًا إتاحة الملف المدفوع مجانًا.
3. النشر يظهر اسم السكربت ووصفه وسعره في المكتبة العامة. اجعل الوصف مناسبًا للنشر العام؛ خطوات الاستخدام والملف المدفوع تبقى محمية.
4. بعد الاتفاق مع العميل، أنشئ اشتراكه وحدد سكربتاته ورمزًا من 9 أرقام ومدة الصلاحية.
5. اختر «تجديد الرمز» لإضافة مدة وإصدار رمز مختلف. انسخ رسالة العميل من النافذة؛ لا يُخزن الرمز كنص مكشوف ولا يمكن استرجاعه كاملًا لاحقًا.
6. تحديث ملف السكربت وإصداره يجعل النسخة الجديدة متاحة لكل عميل مصرح له باشتراك ساري، دون إعادة إنشاء اشتراكه.

رموز الخدمات الخارجية (مثل TKPRO) لا تعمل داخل هذا النظام. لا يوجد نسخ أو تكامل مع خدمة TKPRO، ولا يقوم الموقع بتجميع GPC أو الكتابة المباشرة على الجهاز. صفحة التركيب تعرض هوية MESHARI-ALOTAIBI وتستخدم أدوات Cronus الرسمية لإتمام العمل.
